## 1. 使用前须知

开始前，请准备：

- 一台可以运行 Codex 的电脑；
- 实验室指定 API 服务网站的账号；
- 已开通且仍有余额或调用额度的 API 订阅；
- 从服务网站获取的 API Base URL、API Key 和可用模型名称；
- 一个用于测试的本地项目文件夹。

本指南中的配置项含义如下：

| 配置项 | 含义 | 示例（仅作格式演示） |
| --- | --- | --- |
| API Base URL | 服务商提供的 API 接口地址 | `https://api.example.com/v1` |
| API Key | 用于身份验证的密钥 | `sk-...` |
| Model | 服务商支持的模型标识 | `your-model-name` |

> [!IMPORTANT]
> 示例地址、密钥和模型名称不能直接使用。请以实验室通知及 API 服务网站控制台显示的信息为准。

## 2. 从网站获取 API

### 2.1 注册或登录

1. 打开实验室指定的 API 服务网站：**`[请在此填写网站地址]`**。
2. 注册个人账号，或使用已有账号登录。
3. 按网站要求完成邮箱验证或其他身份验证。
4. 进入控制台，确认账号状态正常。

### 2.2 开通订阅

1. 在控制台中找到“订阅”“套餐”“令牌”或“API”页面。
2. 选择实验室指定的套餐并完成开通。
3. 查看套餐有效期、可用余额、速率限制和支持的模型。
4. 如网站提供“订阅链接”或“一键导入”功能，请不要将该链接公开分享。

> [!NOTE]
> 不同网站的页面名称可能略有差异。若找不到对应入口，请联系仓库维护者或实验室管理员，不要自行购买未确认的套餐。

### 2.3 获取 API 配置信息

在控制台中记录以下三项信息：

1. **API Base URL**：请求接口的基础地址；
2. **API Key**：访问 API 的密钥；
3. **模型名称**：Codex 配置中需要填写的模型 ID。

建议只在密码管理器或操作系统凭据存储中保存 API Key。不要截图传播完整密钥，也不要把密钥写入 README、代码、聊天记录或 Git 提交。

## 3. 安装与启动 Codex

Codex 可通过桌面应用、CLI 或 IDE 扩展使用。本指南重点介绍本地 Codex 配置；不同入口通常共享用户目录下的 Codex 配置。

### 3.1 Codex CLI

已安装 Node.js 和 npm 的用户，可以按照 [Codex CLI 官方文档](https://learn.chatgpt.com/docs/codex-cli) 完成安装。安装后检查版本：

```bash
codex --version
```

进入项目目录后启动：

```bash
cd /path/to/your/project
codex
```

### 3.2 Codex 桌面应用或 IDE 扩展

也可以使用 Codex 桌面应用，或在支持的 IDE 中安装 Codex 扩展。首次打开时，请先选择一个可信的本地项目文件夹。

> [!CAUTION]
> Codex 可以读取和修改当前授权范围内的文件，也可能运行终端命令。开始任务前请确认打开的是正确项目，并仔细检查涉及删除、覆盖、安装软件或访问网络的操作。

## 4. 将 API 订阅导入 Codex

服务商若提供 Codex“一键导入”按钮，可优先按网站说明操作；导入完成后仍应检查 Base URL、模型名称和密钥来源是否正确。若需要手动配置，请使用下面的方法。

### 4.1 设置 API Key 环境变量

以下示例使用 `FSII_API_KEY` 作为环境变量名称。请将 `your-api-key` 替换成自己的密钥。

macOS / Linux（仅当前终端会话）：

```bash
export FSII_API_KEY="your-api-key"
```

Windows PowerShell（仅当前终端会话）：

```powershell
$env:FSII_API_KEY="your-api-key"
```

设置后不要运行会把完整密钥输出到公开日志或截图中的命令。

### 4.2 编辑 Codex 配置文件

Codex 的用户级配置文件默认位于：

- macOS / Linux：`~/.codex/config.toml`
- Windows：`%USERPROFILE%\.codex\config.toml`

如果文件或目录不存在，可以手动创建。将下面内容复制到 `config.toml`，再替换其中的 Base URL 和模型名称：

```toml
# 使用服务商控制台显示的模型 ID
model = "your-model-name"
model_provider = "fsii_provider"

[model_providers.fsii_provider]
name = "FSII API Provider"
base_url = "https://api.example.com/v1"
env_key = "FSII_API_KEY"
wire_api = "responses"
```

配置说明：

- `model`：服务商实际支持的模型 ID；
- `model_provider`：自定义服务商标识，需要与下方表名一致；
- `base_url`：服务商提供的 API Base URL；
- `env_key`：保存 API Key 的环境变量名称；
- `wire_api`：Codex 当前自定义服务商所使用的接口协议。

> [!WARNING]
> 不要在 `config.toml` 中直接填写真实 API Key。官方配置支持通过 `env_key` 从环境变量读取密钥，这样可以降低密钥被误提交或分享的风险。

### 4.3 重启 Codex

保存配置后，完全退出并重新启动 Codex。若使用 CLI，请关闭当前终端会话，在已设置环境变量的终端中重新运行 `codex`。

## 5. 验证配置

打开一个不含敏感数据的测试项目，然后向 Codex 输入：

```text
请只读取当前项目，概括目录结构，不要修改任何文件。
```

如果 Codex 能正常返回结果，说明基础连接已经建立。随后可以让 Codex 执行一个小型、可撤销的任务，并检查其变更内容。

建议同时在 API 服务网站控制台确认：

- 是否产生了新的调用记录；
- 使用的模型是否正确；
- Token 消耗与余额是否正常；
- 是否出现认证失败、限流或接口错误。

## 6. 常见问题

### 6.1 提示未找到 API Key

- 确认环境变量名称与 `env_key` 完全一致；
- 确认 Codex 是从已设置该环境变量的终端启动；
- 修改环境变量后重新启动 Codex；
- 检查密钥前后是否混入空格、引号或换行。

### 6.2 出现 `401` 或 `403`

- API Key 可能错误、过期或已被撤销；
- 账号可能没有目标模型的访问权限；
- 订阅可能已到期或余额不足；
- Base URL 可能与服务商要求不一致。

### 6.3 出现 `404` 或模型不存在

- 检查 Base URL 是否缺少或重复了 `/v1`；
- 模型名称必须与服务商控制台显示的 ID 完全一致；
- 确认服务商接口兼容 Codex 当前要求的 Responses API。

### 6.4 出现 `429`

通常表示额度不足、请求过多或触发速率限制。请稍后重试，并在服务商控制台检查余额、并发数、RPM 和 TPM 限制。

### 6.5 Codex 可以启动，但请求一直失败

- 检查本机网络、代理和防火墙；
- 确认服务商状态页没有故障公告；
- 用一个最简单的只读任务重新测试；
- 保存去除密钥后的错误信息，再联系管理员。

## 7. 其他提醒

### API 与账号安全

- API Key 原则上仅限本人使用，不得转发、公开或上传至网盘共享目录；
- 不要把 `.codex/auth.json`、密钥文件或包含密钥的终端截图提交到 GitHub；
- 一旦怀疑密钥泄露，应立即在服务网站撤销旧密钥并生成新密钥；
- 不要在来源不明的网站、脚本或插件中填写 API Key；
- 离开实验室、设备丢失或账号异常时，应及时联系管理员处理。

### 费用与额度

- API 调用通常按 Token 或服务商套餐规则计费；
- 大文件、长对话、高推理强度和重复重试会增加消耗；
- 使用前确认余额和限额，避免在循环任务中产生意外费用；
- 不要将实验室 API 用于与科研、开发或教学无关的任务。

### 数据与科研合规

- 不要向第三方 API 上传未公开论文、个人信息、受试者数据、密钥或其他敏感材料；
- 涉及保密项目时，应先确认数据处理、留存和跨境传输政策；
- Codex 生成的代码和结论需要人工检查，不应未经验证直接用于生产、实验控制或论文结果；
- 使用 AI 辅助科研写作或编程时，应遵守实验室、学校、期刊和资助机构的披露要求。

### 配置与更新

- API 服务网站和 Codex 的配置方式可能更新，请以最新通知和官方文档为准；
- 修改配置前建议备份原有 `config.toml`；
- 不要直接复制他人的完整配置文件，其中可能包含个人路径、密钥或不适合你设备的权限设置。
